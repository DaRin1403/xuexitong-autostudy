# 模块:自动答题(做题引擎)

> 本文把这个脚本里**"做题"**这一整块拆出来单独讲清楚:题目从哪来、答案从哪来、怎么填、什么时候提交、出错了怎么办。
> 对应代码位于 `学习通刷课助手.user.js` 的「答案通道」「题目提取」「测验/作业/弹题」三个段落(脚本内搜索 `/* ====` 分段注释)。

---

## 1. 一句话原理

```
页面题目 DOM ──提取──▶ 题面+选项+题型 ──字体解密──▶ 干净文本
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                             ①大模型通道(主)     ②免费题库站(默认关)
                                    └─────────┬─────────┘
                                              ▼
                                    答案数组 ["A"] ["ABD"] ["正确"]
                                              ▼
                                     清空 → 勾选 → 校验 → 提交
```

一句话:**提取题面 → 需要时解密字体 → AI 作答 → 自动勾选 → 正确率达标才提交**。

---

## 2. 题面提取(三种容器都要认识)

学习通不同年份的页面结构不一样,脚本对三种容器分别处理:

| 容器 | 出现的页面 | 识别要点 |
|------|-----------|---------|
| `.TiMu` | 章节测验 / 学习检测(旧版) | 题干取 `.clearfix .fontLabel` 或 `.Zy_TItle`;题型取 `input[name^=answertype]` |
| `.questionLi` | 作业页(doHomeWorkNew) | 题干取 `.mark_name` 内 `</span>` 之后的文本 |
| 弹题 iframe | 视频播放中途弹出的题 | 新版弹窗**没有固定 class**,用启发式**多窗口探测**找题目 |

**选项提取做了三级兜底**(学习通选项 DOM 版本差异大):

1. `ul li .after`
2. `ul li`
3. `.answerBg / .num_option / .after`

三级都拿不到才算"没识别出题目"。这也是"为什么有的题脚本不动"的第一排查点。

---

## 3. 字体加密解密(做题正确率的关键)

学习通部分测验会把**题干和选项文字**做成自定义字体混淆(页面上是人眼可读、复制出来是乱码,或者反过来:看起来是乱码)。

脚本的处理方式(`decodeFont`,零依赖):

1. 从页面 `<style>` 里提取 base64 字体,用 `FontFace` 动态加载;
2. 把常见汉字逐个渲染到 **32×32 canvas**,取 alpha > 120 的像素做**位图指纹**;
3. 把页面里被加密的字符也渲染一遍,做**指纹比对**,命中即替换为真字。

命中率会打进日志:`还原 128/130 字符`。**如果日志里这个比例很低,AI 拿到的题干就是残缺的,答案自然不准**——这是排错的高优先级线索。

## 4. 答案通道(1.0.6 现状)

`getAnswers()` 的实际顺序:

| 顺序 | 通道 | 默认 | 说明 |
|------|------|------|------|
| ① | **大模型**(OpenAI 兼容接口) | **需填 Key** | 主通道,准确率最高;未配置时直接跳过并提示 |
| ② | 免费题库站 ×4 | **默认关闭**(`useTiku: false`) | `api.tikuhai.com` / `cx.icodef.com` / `tk.enncy.cn` / `api.muketool.com`,并发查、谁先有结果用谁 |
| — | 都没查到 | — | 记一条 `未查到答案`,该题不填,测验因正确率不达标**不提交** |

**为什么题库站默认关**:这几个站 2025 年起陆续收费/限流,返回的常是"付费/购买/卡密/公众号/扫码"类广告文本。脚本内置 `filterAnswers()` 会把这些词直接过滤掉,但能用 AI 就没必要开它。

> 另有一个**题目收集**功能(独立于查答案):每答完一题就把 题面/选项/答案 存进 `cxQuestions`(上限 5000 条),面板可一键导出 JSON——方便你自建题库或喂给别的工具。

## 5. 大模型通道细节(踩过的坑都在这)

**兼容范围**:任何 OpenAI 格式的 `POST {base}/v1/chat/completions` 都能用——DeepSeek、硅基流动、MiniMax、智谱、通义、Kimi、OpenAI,面板里选供应商 + 点「拉取模型」自动填模型名;也可手填自定义 URL。

**三种题型的提示词**(`buildAIPrompt`):单选要单个字母、多选要字母组合、判断题要 `正确/错误`、填空用 `|` 分隔多空。

**三道保险**(防止推理模型"说一堆话不给答案"):

| # | 保险 | 作用 |
|---|------|------|
| 1 | `system` 消息:"回复的第一个字符必须是最终答案,严禁输出思考过程" | 从对话层面约束 |
| 2 | 用户提示词:"必须以最终答案开头,只输出答案本身" | 再次强调格式 |
| 3 | `reasoning_content` 兜底 | DeepSeek 推理模型有时把结论写在 `reasoning_content`、`content` 留空 → 取推理末尾 300 字解析 |

**失败处理(1.0.5 起改版)**:

- 单次失败不再"永久停用 AI",而是进入 **10 分钟冷却**,冷却期内其他题仍走题库通道;
- 日志会写明原因:`AI 请求失败(1/3): HTTP 401 …`、`网络错误`、`超时(30s)`、`返回内容为空`;
- **常见根因:代理**。如果是全局模式的梯子,`api.deepseek.com` 会被代理劫持(表现为 `HTTP 000`),请退出代理或把 API 域名加入直连规则。

**答案解析**(`parseAIAnswer`):

| 题型 | 解析规则 |
|------|---------|
| 单选 | 取第一个 A–H 字母 |
| 多选 | 取第一段 A–H 字母串,拆成字母数组 |
| 判断 | 含 `正确/对/√/true/是` → 正确,否则错误 |
| 填空 | 按 `|` 切分,去掉空项 |

## 6. 填选与提交

- **先清空再勾选**:避免上一次作答残留(`clearCurrent`);
- **点击三级兜底**:优先点 `input`,`input` 不可点就点它的 label/父级,再不行派发原生事件;
- **提交策略**:全部答完后按 `minAccuracy`(默认 0.6)校验——**低于阈值就只填不交**(保留在页面上,你可以自己检查),达标才点提交按钮。

---

## 7. 节奏配置(1.0.5「极速模式」起默认全 0)

| 配置项 | 默认 | 作用 |
|--------|------|------|
| `answerIntervalMin/Max` | `0 / 0` | 每题之间等待秒数,0 = 立即下一题 |
| `submitDelayMin/Max` | `0 / 0` | 提交前等待秒数 |
| `quizDelayMin/Max` | `0 / 0` | 弹题作答前等待秒数 |
| `deliberateErrorRate` | `0` | 故意答错率(旧版 8%),0 = 不故意错 |
| `minAccuracy` | `0.6` | 低于此正确率不自动提交 |
| `speed` | `2` | 视频倍速(上限 2) |
| `dailyLimitMinutes` | `0` | 每日刷课时长上限,0 = 不限 |
| `useTiku` | `false` | 免费题库站开关 |
| `aiEnabled` / `aiKey` / `aiUrl` / `aiModel` | `false` / 空 / DeepSeek / `deepseek-reasoner` | 大模型通道 |

> 想换成"保守模式"就自己把间隔、答错率、倍速调回拟人化数值——**但请理解**:拟人化只能降低统计特征上的异常,不能"隐藏"自动化行为,风险始终由使用者承担。

## 8. 排错速查

| 现象 | 原因 / 处理 |
|------|------------|
| 日志 `⚠ 未启用 AI 答题` | 面板 ⚙ 勾选「AI 答题」并填 Key |
| `AI 请求失败: HTTP 000` | 代理劫持,退出梯子或配置直连 |
| `HTTP 401 / 402` | Key 错误 / 余额不足 |
| `返回内容为空`、`解析失败` | 换模型(如 `deepseek-chat`)或检查提示词兼容性 |
| `未查到答案` 且无 AI 报错 | 题库通道已关且 AI 未启用,属正常 |
| 题目文字是乱码 | 字体解密失败,看日志里 `还原 N/M` 比例 |
| 完全不动、没有做题日志 | 页面结构不在这三种容器内(新页面),需要加提取规则 |
| 填了但没提交 | 正确率低于 `minAccuracy`,自己核对后手动提交 |

## 9. 想自己扩展

- **加一个题库来源**:在「答案通道」段复制 `channelTikuHai` 的写法(用 `cxFetch` 发请求、`onload` 里 `done(答案数组, 错误信息)`),再加进 `getAnswers` 的 `Promise.all` 列表;
- **换模型/自建中转**:面板选「自定义」,填 `https://你的域名/v1/chat/completions`;
- **加题型**:`buildAIPrompt` 加一个 `case`,同时补 `parseAIAnswer` 的解析分支即可。
